Focused palette controls do not trigger global game shortcuts, and handled gameplay keys do not scroll the page.

## P2 — Shared deterministic engine and verified scores

Completed: moved the six game paths to a shared seeded 20 Hz engine used by the browser and Worker. Ranked starts pin game ID, starting level, starting speed, seed, and rules version in D1. The browser sends action/tick logs only after a true terminal state. Reset abandons a ranked run. The Worker checks owner, time budget, event order, terminal state, and replay bounds, then calculates raw and final scores itself. Casual play remains available when ranked is unavailable and is explicitly marked as unranked in the UI.

Files: `src/engine/`, gameplay classes in `src/games/`, input and panel integration in `src/control/` and `src/components/*panel/`, `worker/src/runs.ts`.

Checks: 26 engine tests cover all six deterministic starts, multiple seeds and levels, terminal traces, chosen speed, manipulated logs, and the Tetris line-bonus regression. Worker integration submits a real Snake terminal trace and confirms that starting level 5 multiplies the server-computed raw score by 5; concurrent finish requests return the same stored result. Across two local `npm run benchmark:replay` executions, per-game median Node replay times ranged 0.055–76.267 ms for natural terminal traces and 12.582–198.05 ms for 12,000-tick pause-padded traces; Tank's 12,000-active-step stress check reached 212.152 ms under parallel load. These are local wall times, **not** Cloudflare billed CPU measurements.

Outstanding: replay CPU in the target Cloudflare runtime and broad real-player gameplay traces need staging measurement. Rules version 1 intentionally changes Tetris to clear lines immediately, keeps the chosen starting speed as a floor, and fixes 1–4 line bonuses to 100/300/700/1500; the old four-line path could produce `NaN`. Next: test more interactive terminal traces on staging before enabling public ranked play.

## P3 — Secure Top 10 claims

Completed: added six independent D1 Top 10 boards, signed anonymous visitor cookies, strict input validation, parameterized queries, endpoint rate limiting, optional server-side Turnstile verification, and a Durable Object that serializes claims and atomically updates board rows and versions. The nickname dialog is gated by a verified and eligible finish response, and claim eligibility is checked again at write time. The UI explains a 409 cutoff race and restores focus when the dialog closes.

Files: `worker/src/`, `worker/migrations/`, `src/components/leaderboard/ClaimNameDialog.js`, `src/api/client.js`.

Checks: isolated local Worker integration passed a 100-contender race, cutoff ties, one-best-per-visitor improvement, idempotent claim retry, concurrent finish, score/game/level spoof rejection, CSRF origin check, nickname injection rejection, and server multiplier. The final board contained exactly 10 rows and only the changed game's version advanced.

Outstanding: the deployed config intentionally has `ENABLE_RANKED=false`; local ranked verification uses an isolated test config. Server-side Turnstile validation exists, but the frontend does not yet render a widget or send a token: setting `TURNSTILE_SECRET` currently rejects all claims. An isolated browser E2E completed Snake start → terminal finish → nickname claim and observed board version 1 with a verified entry. Next: run the broader interactive and abuse matrix on staging; integrate the widget before enabling that optional secret.

## P5 — Hardening and deployment

Completed: frontend tests, Worker integration, TypeScript typecheck, lint, production build, local and remote D1 migrations, Worker runtime/browser smoke, Wrangler deploy dry-run, and the first live deployment. A static `public/_headers` file applies CSP, frame, referrer, and permissions restrictions to the Worker-served assets.
